# Web UI (実験的機能)

← [README](../../README.ja.md)

`--web` を付けると TUI と並行して Web サーバーが起動し、mping を実行しているマシンのブラウザから同じ統計を確認できます。

```bash
mping --web google.com 1.1.1.1      # http://127.0.0.1:8080/ を開く
```

- 待ち受けは loopback のみ (`127.0.0.1`、利用可能なら `[::1]` も) で、他のマシンからは接続できません。`Host` / `Origin` ヘッダがこのサーバー以外のリクエストは拒否します (DNS rebinding・クロスサイト対策)。
- ブラウザとやり取りする部分は別プロセスで動き、mping と一緒に起動・終了します。このプロセスは何かを配信する前に権限をすべて恒久的に捨てます。起動したユーザー（`sudo` の場合は呼び出したユーザー、root が直接起動した場合は `nobody`）として動き、Linux ではインストール時に付けた `CAP_NET_RAW` や setuid root も得られません。計測データには、そのユーザーだけが開ける専用ディレクトリ内の UNIX ソケット経由でアクセスし、操作用 token の確認は mping 本体が行います。OS によっては非特権プロセスが低いポートを利用できないため、`--web-port` は 1024 以上を推奨します。
- TUI の Log に表示される操作用リンクには秘密の token が含まれます。token を自分で決める場合は、環境変数 `MPING_WEB_TOKEN` で指定し (英数字と `-._~` で 16 文字以上。コマンドラインやシェル履歴に残さないでください)、`http://127.0.0.1:8080/#token=<指定した token>` を開いてください。
- `--web` / `--web-port` は起動時にのみ読み込まれます。hosts ファイルのリロードではサーバーは再起動しません (hosts ファイルで変更すると「再起動が必要」という警告を Log ペインに表示します)。
- PC のダッシュボードはブラウザの横幅・高さ全体を使います。詳細エリアには選択中ホストの **Summary**（未選択時は **Activity**）を表示します。ホスト数が少ないときは一覧の高さが行数に合わせられ、その下に詳細エリアが横幅いっぱいに並びます。行数が画面の高さの約半分を超えると、詳細エリアは右側の全高カラムへ移ります（境界付近で頻繁に切り替わらないよう余白を持たせています）。経路監視が有効な場合は一覧の下（少ホスト時は詳細エリアの横）に配置されます。選択中のホストをもう一度選ぶか **Esc** を押すと Summary を閉じます。
- **Activity** には各ホストの現在の状態・アドレス・継続時間（対象が多い場合は要注意ホストのみを継続時間順）、保持イベントから集計した直近 1 時間のサマリー（状態変化数・最も不安定なホスト・5 秒以内に 3 台以上が同じ指標を超過したタイミング。古いイベントが上限を超えた場合は下限値として表示）、および全ホストの最新イベントを表示します。各ペインは内部でスクロールし、狭いウィンドウでは縦に並びます。スマートフォンでは上部バーが折り返され、幅の広い表はペイン内で横スクロールできます。**Summary** には状態と継続時刻、閾値付きの判定理由、RTT / Jitter / 直近 Loss / TTL のタイル、RTT チャート、直近イベント、および折りたたみ可能な **Details** 配下の累積統計・ポート監視・対象操作をまとめます。
- 経路表示はオプションに従います: **`-T` → Tracerouteペイン**、**`-M` → MTRペイン**。どちらもホスト選択なしで全対象を表示し、一覧のフィルターに連動します。Tracerouteは番号付きの縦経路にAS／PTRをオプションに応じて表示します。MTR では対象ホストの見出しがホップと一緒にスクロールし、列見出しは固定されます。MTR の対象ホストの見出しには、ホップ数または `Waiting for hops` を表示します。Traceroute ではホップの総数と応答がなかったホップ数を表示します。ホップの損失色は、そのホップ以降の最小損失率を対象の Ping の損失閾値で判定して決まります。MTRはTTL／Hop Limitを制限したICMP Echo方式で、UDPモードはありません。
- **Log** は上部ナビゲーションから開く独立画面で、全ホストの最新200件のイベントを表示します。表示中は 5 秒ごとに更新し、イベントの種類とホスト名で絞り込めます。絞り込み条件はページの再読み込みでリセットされ、**Clear filters** でも両方の条件を解除できます。状態変化には状態記号を表示し、警告と異常は行に色を付けます。有効な **HTTP** 監視は独立画面で、応答時間は通常色で表示します。Summary のポート監視で応答がタイムアウトした場合は `timeout` と表示します。Monitorに戻ると選択中のSummaryと各ペインのスクロール位置を復元します。
- **RTT · 60s** 列の見出しには、全行のスパークラインで共有するスケールを表示します。各スパークラインのツールチップには区間内の最小・平均・最大 RTT とロス数が表示されます。ロスは赤い縦線、1 分間すべて無応答の場合は赤い破線で描かれます。Summary の RTT チャートは選択した期間（既定 5 分）を表示し、大半のサンプルが収まるスケールに自動調整されます。スケールを超える大きなスパイクは上端で切り詰められ、ピーク値とともに **▲** で示されます（例: **▲ 680 ms**）。応答のあるホストの大半（3 台以上かつ 75% 以上）が同時に同じ閾値を超過すると、一覧の上に **Common cause** バナーを表示します。
- 設定順で表示すると、グループ見出しには異常、警告、結果待ち、停止のホスト数が深刻な状態から順に並びます。全台正常なら `○ all OK` と表示します。一覧は画面の幅に収まる限りの列を表示し、狭いときは重要度の低い列から隠します (状態・ホスト・ロス率・最新RTTは常に表示)。各行には超過した指標と値（例: **Jitter 50.5 ms**）を表示し、閾値はツールチップと Summary で確認できます。開始／リセット以降の平均・最小・ピーク RTT は Summary に表示し、Summary チャートの数値読み取りはカーソル位置に表示されます。広い画面では一覧と詳細を並べて表示します。閲覧専用の場合は **Enable controls** から token または TUI でコピーした URL 全体を貼り付け、再読み込みせずに操作を有効にできます。入力した token は検証成功後に保存し、接続失敗と token の拒否は別のメッセージで案内します。
- 列幅・行高は計測値の更新で変わらないレイアウトです。表示幅に応じて列数を調整し、Status・Host・Loss %・最新RTTを残します。倍率の選択は不要です。Inspectの横スクロール位置も更新時に保持します。長い名前や IPv6 は省略表示し、全文はツールチップや詳細で確認できます。大きなカウントは M/B/T、非常に大きな RTT は指数表記にし、元の値はツールチップに残します。[列幅と表示桁数の仕様](../../internal/web/COLUMNS.md)を参照してください。
- **ブラウザからの操作**: `--web` 指定時はTUIヘッダーに接続先と **b** キーの案内を常設します。一覧・ホスト詳細で **b** を押すと、現在のtoken付きURLをいつでも表示できます。**Copy URL**（Enter）で端末にクリップボードへのコピーを依頼し、**Esc** で元の画面に戻ります。端末がコピーに対応していない場合は表示されたURLを選択してください。Logの保持件数やスクロール位置には依存しません。起動時には従来どおりLogにも表示します。表示されるリンク (例: `Web UI: http://localhost:8080/#token=…`) を開くと、ホストの追加・確認ダイアログを経たターゲットの削除・統計のリセットができます。token は起動ごとに生成され、操作内容は TUI の Log ペインにも記録されます。token なし (または以前の起動時の token) で開いた場合は閲覧のみです。同じ token でTUIと共通の Stop / Restart、レポート保存も利用できます。**Report** ボタンを押すと、**JSON／CSV** と保存するファイル名を指定できます。拡張子は選択した形式に合わせ、CancelやEscでダウンロードせずに閉じられます。
- ヘッダーの状態別件数ピル（Critical / Warning / OK、および結果待ちがある場合は Waiting）で一覧と経路ペインを絞り込めます（選択中のピルをもう一度押すと全件表示に戻ります）。検索と状態を組み合わせ、表示件数／全件数を常時確認できます。列見出しや選択欄からグループをまたいで並べ替えでき、ホストの下にはグループ名を残します。計測値が変わっても順序は固定し、**Refresh order** で順位を更新します。**Configured order** で元のグループ順に戻り、固定中に追加したホストは末尾に表示します。
- 選択ホストは一覧と経路ペインで強調します。**Selected host** を押すと対応するペイン内の対象へ移動します。選択や計測更新で他のペインを自動スクロールしません。選択対象が絞り込みから外れても Summary を維持し、その旨を表示します。Summary は現在・直近の状態、開始／リセット以降の統計、ネットワーク詳細の順です。
- ヘッダーの接続インジケータ（**Live** / **Stopped** / **Reconnecting** / **Session ended** など）はホストの健全性とは独立しており、実際の最終プローブ時刻を表示します。再接続中は以前の値を保持し、いつの時点の値かを案内します。通知はワークスペース上に重ねて表示し、エラーは閉じるまで残します。**Stop all / Restart all** は統計を維持します。削除・リセットは対象範囲を明示し、Cancel に初期フォーカスを置いた期限のない確認ダイアログで実行します。
- **?** でキー操作の説明と文字ショートカットの有効／無効設定を開きます。**/** で検索、一覧内の **j/k** または **↓/↑** でフォーカス移動、**Home/End** で先頭／末尾、**Enter** で選択、**Delete** で削除確認、**w** で Report、**Esc** で検索を離れる／ダイアログを閉じる操作ができます。入力欄・IME 変換・ブラウザの修飾キー操作は妨げません。Summary チャートにフォーカスして **←/→**・**Home/End** を使うと、時刻と RTT／ロスをテキストでも確認でき、**Esc** でカーソルを消せます。
- 時刻はシステムのタイムゾーン・24時間表記です。AS・PTR・PMTUの表示は、SummaryやMTR内も含めて各オプションに連動します。
- 同じデータを JSON でも取得できます:

| エンドポイント | 内容 |
|---|---|
| `GET /api/v1/snapshot` | 現在の統計 (`snapshot` 配下)、`meta` (有効な機能・閾値・グループ)、`state` (`starting` / `running` / `reloading` / `stopped`) |
| `GET /api/v1/events?limit=200` | 全ターゲットのイベントを新しい順に 1 つのリストで返す (ホスト名付き、`limit` は 1–1000) |
| `GET /api/v1/history?n=60` | 全ターゲットの直近 RTT を 1 回のレスポンスで返す (`n` は 1–3000) |
| `GET /api/v1/stream` | Server-Sent Events。接続時と、統計が変化している間は最大 1 秒に 1 回 `snapshot` イベントを送信 |
| `GET /api/v1/targets/{id}/history?n=300` | 互換用 `rtt_ms`、時刻付き `samples` (`at`, `rtt_ms`)、取得時刻 `captured_at`。古い順で `null` は応答なし (`n` は 1–3000) |
| `GET /api/v1/targets/{id}/events` | ターゲットの記録済みイベント (DNS 変化・経路フラップ・ロス) |
| `GET /api/v1/session` | 有効な `X-Mping-Token` ヘッダ付きなら `{"control": true}` |
| `POST /api/v1/targets` | ホスト追加。JSON `{"host": "example.com"}`、`X-Mping-Token` が必要 |
| `DELETE /api/v1/targets/{id}` | ターゲット削除。`X-Mping-Token` が必要 |
| `POST /api/v1/reset` | 統計リセット。`X-Mping-Token` が必要 |
| `POST /api/v1/stop`, `POST /api/v1/restart` | 統計を保持して一時停止・再開。`X-Mping-Token` が必要 |
| `GET /api/v1/report?format=json` (`csv` も可) | サーバーにファイルを作らずレポートをダウンロード。`X-Mping-Token` が必要 |
